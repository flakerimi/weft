# Changelog

What each release of Weft brought. Every 0.0.x release may change any name;
from 1.0.0 on, what is removed is deprecated first (see `docs/roadmap.md`).
A release is published at weft.base.al and as a GitHub Release of the same
name, with the same archives and `SHA256SUMS`, from 0.0.12 on. Releases before
0.0.12 have no GitHub Release: they were published at weft.base.al, and
`site/releases.txt` lists them (only 0.0.1 and 0.0.2 have a tag).

## Unreleased

- Accounts (0.2.0). The login has four roles, owner, administrator, member
  and viewer, with permissions by grant (`auth.Grant`); sessions kept in a
  table, so one or all can be ended; invitations, sign-up
  (`AUTH_REGISTRATION`, `invite` by default) and password reset by mailed
  links; a count of failed logins per account across addresses; and API keys
  (`API_KEYS=on`). A reset ends every session and deletes the user's API
  keys; a password change ends the other sessions and keeps the keys.
- The `mail` module prints each message to standard error, framed and as it
  is, so a link copies from a terminal (the log gets one line, `mail
  printed`, with no body), or sends it over SMTP from a queue in memory;
  `mailtest` reads it in tests. `auth` needs it: an app made
  before lists `mail.Module()` before `auth.Module()` in `app/modules.go`.
- The `middleware` module adds security headers to every answer, one log line
  per request (`LOG`) and a rate limit on `/api` (`RATE_LIMIT`); `WrapAll`
  wraps every request an app answers; the server times out a slow request
  (30 s) and an idle connection (120 s).
- `@weft/ui` has `useSession()`, `requireSession()`, `sessionEnded()`,
  `nextPath()`, `perm` on `Button` and `DataTable`, and `Guard`. An app's own
  `web/session.ts` is no longer written; `weft create` writes pages to sign
  up, reset a password, and manage one's account and the users, and
  `weft scaffold` guards its pages by permission.
- Date and time fields: the `date` rule, `format` in the generated schema,
  date and time controls in `EntityDialog` (`useDateFields()`), and date
  fields in the pages `weft scaffold` writes.
- Upgrading from 0.0.24: `weft upgrade` lists `mail.Module()` before
  `auth.Module()` in `app/modules.go` (or, when it cannot edit the list,
  says the line to add and exits 1 before it writes anything), writes the
  pages and forms the login's links open (`/password`, `/forgot`,
  `/register`, `/account`, `/users`) and `web/session-check.ts` where the app
  lacks them, never writing over a file (an app already on the version still
  gets them), and says to list `middleware.Module()` first; an old
  `web/session.ts` is kept and can go once no page imports it. Everyone signs
  in once after the upgrade.

## 0.0.24

- Chrome's Issues panel is empty on weft.base.al. `Input`, `InputNumber`,
  `Textarea` and `InputTime` always have an id: their field's or the `id`
  prop's when there is one, else one generated by `useId`, so a cleared or
  changed id never leaves a control with none. `CommandPalette`'s search
  input, `DateRangePicker`'s inputs (with unique ids outside a FormField) and
  every `PinInput` box have ids, and the landing's lazy image keeps its aspect
  ratio, so it raises no lazy-load warning.

## 0.0.23

- Vue 3.6.0-rc.17, from rc.16, and `scripts/vue-update.sh`, which moves every
  pin to the newest 3.6 build. rc.17 writes other hydration markers in a server
  render (`<!--[!-->` and `<!--[$-->`, every range closed by `<!--]-->`, and no
  range around a single root that is a component), which only rc.17's runtime
  hydrates; a build renders and bundles the same Vue, and Weft's own code reads
  none of them. The Vapor runtime is about 0.6 KB brotli larger, and pages a
  little smaller.

## 0.0.22

- A FormField's label is a `<label for>` only over a labelable control. Over a
  RadioGroup, CheckboxGroup, Slider, Listbox without a filter, ToggleGroup or
  InputTime's parts it is a `<span>` the control is `aria-labelledby`, drawn so
  by the server too, so a static page has no `<label for>` naming a fieldset, a
  thumb or a list (Chrome's "Incorrect use of <label for=FORM_ELEMENT>"). An
  InputTime on touch is a native time input the label is for; a ToggleGroup
  takes its field's id and label; with no label, no control points
  `aria-labelledby` at one; and what the `label` slot holds is no control of
  the field's, with ids of its own in an island. Mounted in the browser with no server
  HTML, the label is drawn one update after `mount()`, before anything is
  painted.
- Three new themes in `@weft/themes`: `synthwave` (neon on deep violet,
  Space Grotesk), `editor` (a warm charcoal code editor with candy accents,
  JetBrains Mono for everything) and `sandstorm` (sand, dune ochre and dusty
  terracotta, rounder corners, Quicksand), each passing the contrast checks
  in light and dark. `weft create --theme`, `weft-build-pages --theme` and
  `weft-dev --theme` take them.
- The page build builds a stylesheet a page imports by its URL
  (`import href from './x.css?url'`) as a file of its own under `/assets/`,
  minified, named by its bytes and cached for good, with the fonts it names;
  it is never inlined and its fonts are not preloaded. An island that imports
  one is refused; `weft dev` serves it.
- weft.base.al's header has a Theme menu that switches the whole site to any
  of the six themes, kept across pages and visits and applied before the
  first paint; each theme but `weft` and its fonts (Inter for Neutral, Rubik
  for Lisa, Space Grotesk for Synthwave, Quicksand for Sandstorm) load only
  when picked.
  The gallery's stage shows the picked theme too, unless its toolbar forces
  Neutral or Lisa. The docs have pages of their own for `weft scaffold` and
  for validation and errors.

## 0.0.21

- Windows is supported on amd64 and arm64: `irm https://weft.base.al/install.ps1 | iex`
  installs `weft.exe` into `$HOME\.local\bin` and adds it to the user `PATH`;
  `scripts/release.sh` builds all six targets (`darwin`, `linux` and `windows`
  on `amd64` and `arm64`) by default, so published releases and GitHub Releases
  carry the Windows `.zip` archives alongside the tarballs; `weft update` names
  the PowerShell installer on Windows; and the docs cover Windows.

## 0.0.20

- On a phone (under 640 px) the landing's phone picture follows the install
  command closely, 64 px below the copy, over a shorter band of the weave
  (700 px), in place of a 180 px gap over an 816 px band.

## 0.0.19

- On Windows, `weft dev` and the commands that run child processes put each
  child in a Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) while suspended,
  so stopping a child or ending `weft dev` (even with `TerminateProcess`) ends
  its whole process tree.
- On Windows, `weft dev` gives the Go server and the page server a stdin pipe
  each, so the page server no longer waits behind the Go server's read and
  starts; a Job Object that cannot be made is said in its own sentence.
- The license is held by Flakerim Ismani and Basecode LLC, and the site's
  footer links basecode.llc over https.

## 0.0.18

- `weft scaffold <name> <field[:type[:modifier...]]>...` writes a resource:
  its Go package (model, routes and a story test, added to `app/modules.go`)
  and a `DataTable` page with a record page, or the API alone with `--api`,
  then runs `weft gen`. A field's type is written, never guessed (`string`
  when none is given), `enum=a,b` among them; the modifiers are `nullable`,
  `required`, `unique`, `min=` and `max=`; the plural can be given with
  `--plural`. What it cannot write is refused in one sentence, writing
  nothing. `date` and `datetime` fields need `--api` until 0.2.0.
- The app `weft create` makes is in the example shop's shape: `data`, `auth`
  and `hello`, the login and setup pages, a fresh `AUTH_SECRET` per app, and
  the SQLite driver.
- A fresh app's `go test ./...` builds before the first `weft build`, from
  the page build's empty marker in `web/dist`; a binary built before
  `weft build` refuses to start instead of serving nothing.
- A `Footer` in an island keeps its width through hydration; `useWidth`
  reads a stored width back only inside an island.
- The CSP docs collect the speculation rules' hash with the pre-paint ones;
  `'inline-speculation-rules'` is not offered, since Chrome ignores it beside
  a hash.
- An integer `enum=` choice must be written as its type prints it (`+5`, `-0`,
  `05` and `-05` are refused), and an unsigned one out of range is told its
  range.
- A page counts as run-time only from `export const runtime = true` or a
  `const` exported as `runtime`.

## 0.0.17

- `DataTable`: a resource's list with server paging, sorting, a debounced
  search and filters, creating and editing through `EntityDialog` and
  deleting through `ConfirmDialog`, with focus kept on a row action after a
  delete.
- `EntityDialog`: controls made from a schema, `fields` as an ordered
  `EntityFieldConfig[]`, only changed fields sent on update, and server errors
  shown on their fields or in one `Alert` read out to screen readers.
- `Table` keeps its search debounce with an inline `fetch`, and `refresh()`
  settles when a newer request supersedes it. `Form` focuses the first
  invalid field once it is no longer busy.
- `scripts/publish-site.sh` and `rollback-site.sh` refuse `--dry-run` anywhere
  but first, an option they do not know, and a second argument;
  `github-release.sh` the same past its optional folder; each before anything
  is built, tagged or pushed.

## 0.0.16

- The older width-adaptive components (`Stepper`, `Timeline`, `Tabs` and
  others) are measured before paint and keep their width through hydration;
  every width measure reads one box, and `useViewportWidth()` sees the
  viewport as its media query does.
- Text on a tint of the text colour is drawn in the full text colour; the
  selected pill tab is marked by its tone, or a ring in the neutral tone.
- The page dev server's reload waits at most a second.

## 0.0.15

- An `enum` field is typed as the union of its values in the generated
  client, and `useParams('/pattern')` is typed from the routes in `pages/`.

## 0.0.14

- `useWidth`'s hydration lookup is keyed by `useId`, and the docs say how to
  collect the CSP hashes of several pre-paint scripts.

## 0.0.13

- Landing blocks: `Hero`, `FeatureGrid`, `Pricing`, `Testimonials`, `Faq` and
  `Cta`.
- `useWidth` measures before the first paint, with one page-wide pre-paint
  script, so width-adaptive components adapt on static pages.

## 0.0.12

- A publish tags its commit `v<version>` and makes the GitHub Release with
  the archives and `SHA256SUMS` the site serves; an app's `go.mod` requires
  `github.com/flakerimi/weft` at the release's tag, from GitHub.
