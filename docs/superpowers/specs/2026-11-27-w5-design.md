# W5: Scaffolding, `DataTable`, `EntityDialog` and the App Template

Date: 2026-11-27
Extends `2026-11-23-warp-design.md` (Phase W5) and `2026-11-25-warp-slice-design.md` ("After the slice").

## Intent

The slice (`examples/shop`) proved Warp's end-to-end story on SQLite: `data.Module()`, `auth.Module()`, `data.Resource`, `weft gen` writing the typed client and `schema`, a products table with server-side paging, sorting, search and filters, a dialog that creates and edits records against the generated schema, and a run-time page for one record.

It also showed what the app still had to write by hand (`examples/shop/web/components/ProductsTable.vue`, 201 lines, and the workarounds listed in `2026-11-25-warp-slice-design.md:182-218`):

1. `Table`'s `search` prop triggers `fetch` on every keystroke, with no debounce (slice item 11).
2. Every CRUD dialog writes the same state management (`open`, `editing`, `draft`, `formKey` to clear errors on reopen, `changes()` to send only changed fields on `PATCH` and skip the request when nothing changed, and `formProblem` to map an `ApiError`'s `fields` onto the form and show non-field or unknown-field errors in a top `Alert`, with one sentence for `code === 'network'`) (slice items 4, 6, 8, 10).
3. Every CRUD table page wires a search input, filter controls, a "New <resource>" button, a row actions column (`Edit` and `Delete`), an `EntityDialog` for create/edit, and a `ConfirmDialog` for delete that shows an `ApiError` inside the confirmation dialog and refreshes the table on success.
4. `templates/app/` (`weft create`) is still the one-route `hello` app with no database, no login, and no `.env` secret (slice item 19), and `weft scaffold` does not exist yet.

W5 closes all four:

- **`Table` debounced search** (`packages/ui/src/data/useTableData.ts`, `Table.vue`): server-side `search` is debounced before asking `fetch`, cancelling any pending timer on a new keystroke and ignoring answers or errors from superseded requests.
- **`EntityDialog`** (`packages/ui/src/data/EntityDialog.vue`): a modal dialog that creates (`create(body)`) or edits (`update(id, changed)`) a record against a generated `schema` (`Record<string, FieldRules>`), auto-rendering controls from the schema (or taking custom controls through its default or per-field slots), diffing edits so `update` receives only the changed fields (and closes without a request when nothing changed), and mapping `ApiError` field and top-level errors cleanly.
- **`DataTable`** (`packages/ui/src/data/DataTable.vue`): a server-backed data block around `Table`, `EntityDialog` and `ConfirmDialog` that takes `:resource="api.products"` (or individual `:fetch`, `:create`, `:update`, `:remove` functions) and `:schema="schema.ProductInput"`, draws the search bar, filter controls, "New" button and row actions (`Edit`, `Delete`), and turns `examples/shop/web/components/ProductsTable.vue` into a declarative component.
- **`weft scaffold` and the app template** (`cmd/weft/scaffold.go`, `templates/app/`): `weft create` writes the shop's frame (`data`, `auth`, the login and setup pages, `web/session.ts`, `.env` with a fresh random `AUTH_SECRET`, and `hello` kept as the public route), and `weft scaffold <name> <field[:type[:modifier...]]> ... [--api]` generates `app/<plural>/{model,routes,<plural>_test}.go`, registers `<plural>.Module()` in `app/modules.go`, generates the pages under `web/pages/<plural>/`, and runs `weft gen`.

## Goals

- `Table` debounces server-side `search` changes so typing a word in the search box does not fire a request on every keystroke, while clearing search or changing `sort`, `filters` or `page` asks immediately.
- `EntityDialog` and `DataTable` are first-class Vapor components in `@weft/ui` (`packages/ui/src/data/`), exported from `@weft/ui`, documented in `.docs.md` with examples and catalogue entries, and used by `examples/shop` (cutting `ProductsTable.vue` from ~200 lines of hand-wired dialog/confirm/diff/error boilerplate to a declarative `<DataTable>`).
- `weft create myapp` produces an app with `data.Module()`, `auth.Module()` and `hello.Module()`, SQLite configured in `.env` with a generated 48-byte base64url `AUTH_SECRET` (`.env.sample` keeps a placeholder) and `AUTH_OWNER_EMAIL=owner@example.com` (printing a line saying to set `AUTH_OWNER_EMAIL` in `.env`), and `/login` and `/setup` pages ready to use.
- `weft scaffold product name:string:required:max=120:unique price:float:min=0 sale:float:nullable status:enum=draft,live:required` in a created app writes `app/products/{model,routes,products_test}.go`, adds `products.Module()` to `app/modules.go`, writes `web/pages/products/index.vue` and `web/pages/products/[id].vue` (unless `--api` is given), runs `weft gen`, and passes `go test ./...`, `pnpm typecheck` and `weft build`.

## Non-goals

- Relations (`belongs_to`, `has_many`, `many_to_many`) and soft delete (milestone `0.3.0`, W3). `weft scaffold` refuses them with one sentence naming the field and `0.3.0`.
- Attachments (`image`, `file`; milestone `0.4.0`, W6) and `json` or `translated` fields (milestone `0.6.0`, W7). `weft scaffold` refuses them with one sentence naming the field and the milestone.
- Lifting `useSession()` into `@weft/ui` or adding a `ready` prop to `DataTable` (milestone `0.2.0`, W4). Whether a visitor is signed in stays the page's concern; the page renders `DataTable` when ready.

## Approaches

1. **Code-generate the entire 200-line `ProductsTable.vue` into every scaffolded page, with no `DataTable` or `EntityDialog` in `@weft/ui`.**
   - *Pros:* Zero new components in `@weft/ui`.
   - *Cons:* Every scaffolded resource duplicates 200 lines of diffing, error-mapping, dialog-reset and confirm-delete logic; fixing a bug or improving keyboard/adaptive behavior in CRUD pages cannot travel through `weft upgrade`. Rejected.
2. **Monolithic `DataTable` that owns the dialog and cannot be split, with no standalone `EntityDialog`.**
   - *Pros:* One component to add.
   - *Cons:* An app that wants a "Create" or "Edit" dialog on a detail page (`/products/[id]`), in a header action, or without a table still has to write `changes()`, `formProblem()` and `formKey` by hand. Rejected.
3. **Standalone `EntityDialog` + `DataTable` that composes `Table`, `EntityDialog` and `ConfirmDialog`, both in `packages/ui/src/data/`, paired with explicit-type `weft scaffold` and a frame-only app template (chosen).**
   - *Pros:* `EntityDialog` is usable on its own anywhere an app creates or edits a record; `DataTable` composes `Table`, `EntityDialog` and `ConfirmDialog` over the exact `{ list, create, update, remove }` shape `weft gen` writes; `Table` itself gets the search debounce so plain tables benefit too; `weft scaffold` generates small, readable files that use `DataTable`; and the template gives every new app `data` + `auth` + `hello` without a dummy starter resource to delete.

## Calls (agreed by Fable and Argon, 2026-11-27)

- **`EntityDialog` lives in `packages/ui/src/data/`** beside `DataTable` (it is the data block's dialog) and is exported from `@weft/ui` for standalone use.
- **`EntityDialog` sends only changed fields on `update`**, and when nothing changed it closes and emits nothing without sending a request.
- **`EntityDialog` maps errors in one place:** an `ApiError` with `fields` sets the errors of the fields present in the form, and any `fields` key not shown in the form (such as a hidden token or a server rule on an unlisted field) or any top-level error message is shown in one `Alert` (`tone="danger"`) at the top of the form; `code === 'network'` shows `'The server could not be reached; check the connection and try again.'`; any non-`ApiError` logs to `console.error` and shows `'Something went wrong on this page; reload it and try again.'`. Raw runtime error text is never shown to the visitor.
- **`EntityDialog` auto-renders controls from `schema`** when no default slot is provided: `enum` with 4 or fewer choices renders a horizontal `RadioGroup` on `regular` and `wide` widths and a `Select` on `narrow` (and `Select` at every width when an `enum` has more than 4 choices); `boolean` renders `Checkbox`; `number` renders `InputNumber`; `string` renders `Input` (`type="email"` when `rule.email`, `type="url"` when `rule.url`, `Textarea` when `fields` marks `control: 'textarea'`).
- **Debounced search lives in `Table` (`useTableData`)**, not only `DataTable`: when `search` changes to a non-empty string while `fetch` is used, `useTableData` waits `searchDebounce` ms (default `250`, configurable via `searchDebounce?: number` on `Table` and `DataTable`; `0` disables the wait) before calling `fetch`. A new keystroke cancels the timer; clearing `search` to `''`, or changing `sort`, `filters` or `page`, cancels any pending search timer and asks at once; an answer or `ApiError` from an earlier in-flight request is ignored (`mine !== asked`).
- **No `ready` prop on `DataTable`.** Session readiness belongs to the page (and later W4's `useSession`); the page renders `DataTable` when ready (`v-if="ready"`).
- **`DataTable` takes `:resource="api.products"` directly**, matching the `{ list, create?, update?, remove? }` object `weft gen` writes for a `data.Resource`, or individual `:fetch`, `:create`, `:update`, `:remove` props. The row actions column (`Edit`, `Delete`) and the toolbar's `"New <name>"` button appear only for the actions the resource provides (`create` → New button; `update` → Edit row button; `remove` → Delete row button).
- **`weft scaffold` uses explicit field types with no name-based inference and no hidden `max=120` on `string`.** A field without `:type` is `string`. Modifiers are `:nullable` (`sale:float:nullable` → `*float64`, `| null` in TypeScript), `:required`, `:unique`, `:min=N` and `:max=N`, in any order after the type, and nothing is required, nullable or length-bounded unless written. (Amended 2026-11-27: the first form, `?` after the type, is a pattern to zsh, the macOS default shell, which stops before `weft` runs; a `?` anywhere in a field argument is refused with one sentence showing the `:nullable` form.) `enum` choices are written in one shell-safe comma form only: `status:enum=draft,live` (written into the Go `warp` tag as `enum=draft|live`; a `|` or `(` in the argument is refused with one sentence showing the comma form).
- **No plural detection in `weft scaffold`.** Only reserved names are refused; the deterministic pluralizer runs by default, `--plural <word>` overrides it, and the chosen plural is printed in the list of files written.
- **Labels, not hardcoded English, in components:** `EntityDialog`'s `noneOption` (`'None'`) for an optional enum and `DataTable`'s `anyFilter` (`'Any'`), `booleanYes` (`'Yes'`) and `booleanNo` (`'No'`) come from `labels` with those defaults.
- **Numbers in `EntityDialog` and `weft scaffold`:** `float` leaves `step` unset unless passed in `fields` (e.g. `step: 0.01` for money in the shop), and scaffolded tables format numbers with `toLocaleString()` rather than assuming two decimal places.
- **`data` tags come from the field's type, not its name:** every scalar field (`string`, `email`, `url`, `int`, `float`, `date`, `datetime`, `enum`, `bool`, except `text`) gets `sort`; text fields (`string`, `text`, `email`, `url`) get `search`; `enum` and `bool` get `filter`.
- **The app template (`templates/app/`) takes the shop's frame, not its resource:** `data.Module()`, `auth.Module()` and `hello.Module()`, the SQLite driver in `main.go` and `go.mod`, `.env` with a fresh 48-byte base64url `AUTH_SECRET` generated by `weft create` (`.env.sample` keeps a placeholder) and `AUTH_OWNER_EMAIL=owner@example.com` (`weft create` prints a line saying to set `AUTH_OWNER_EMAIL` in `.env`, and the getting-started guide says so too), and the login and setup pages (`web/pages/login.vue`, `web/pages/setup.vue`, `web/components/LoginForm.vue`, `web/components/SetupForm.vue`, `web/session.ts`, `web/answers.ts`). `hello` stays as the public route so `GET /api/hello` answers before anyone signs in.

## Detailed Design

### 1. `Table` Search Debounce (`packages/ui/src/data/useTableData.ts`, `Table.vue`)

In `Table.vue` and `useTableData.ts`:

- Add optional prop `searchDebounce?: number` to `TableProps` (default `250`).
- In `Table.vue`:
  - The watcher that resets `page.value = 1` when `search` or `filters` change must not cause a double fetch or an immediate fetch before the debounce expires. Specifically, when *only* `search` changed to a non-empty string and `searchDebounce > 0`, `useTableData` schedules the fetch after `searchDebounce` ms, resetting `page` to `1` when the debounced query fires (or resetting `page` immediately while holding the `ask()` call until the timer fires).
- In `useTableData.ts`:
  - Track `let timer: ReturnType<typeof setTimeout> | undefined`.
  - When the watched query sources change:
    - If only `opts.search?.()` changed, its new trimmed/raw value is non-empty (`Boolean(q)`), `remote.value !== null` (initial mount always fetches immediately!), and `(opts.searchDebounce?.() ?? 250) > 0`:
      - Increment `asked` immediately so any in-flight request from before the keystroke cannot overwrite the table or emit a stale `error` while waiting for the debounce timer.
      - Clear any previous `timer` and set `timer = setTimeout(() => { timer = undefined; void ask() }, delay)`.
    - Otherwise (initial mount, `search` cleared to `''`, or `page`, `perPage`, `sort`, `filters` or `fetch` changed, or `load()` was called):
      - Clear any pending `timer` (`clearTimeout(timer); timer = undefined`) and call `void ask()` immediately.
  - Clean up `clearTimeout(timer)` on scope disposal (`onScopeDispose`).

### 2. `EntityDialog` (`packages/ui/src/data/EntityDialog.vue`, `entity.ts`)

`EntityDialog` is a Vapor component `<script setup vapor lang="ts" generic="T extends Record<string, any> = Record<string, any>, TInput extends Record<string, any> = Record<string, any>">`.

#### Types (`packages/ui/src/data/entity.ts`)

```ts
import type { FieldRule } from '../forms/schema.ts'

/** A field's rules and kind as `weft gen` writes them in `schema.<TypeInput>`. */
export interface EntityFieldRule extends FieldRule {
  kind?: 'string' | 'number' | 'boolean' | 'list' | 'record' | 'object' | 'unknown'
}

export type EntitySchema<Name extends string = string> = {
  [K in Name]?: EntityFieldRule
}

/** Optional presentation override for one field in EntityDialog. */
export interface EntityFieldConfig {
  /** The field's key in `schema` and `state`. */
  name: string
  /** Label shown on the FormField; default humanized from `name` (`created_at` → `Created at`). */
  label?: string
  /** Hint text under the FormField. */
  hint?: string
  /** Placeholder text for text/number/select controls. */
  placeholder?: string
  /** Control override: `'textarea'` for multi-line text, `'select'` or `'radio'` for enum, `'switch'` or `'checkbox'` for boolean. */
  control?: 'input' | 'textarea' | 'number' | 'select' | 'radio' | 'checkbox' | 'switch'
  /** Step for InputNumber (e.g. `0.01` for money, `1` for integers). */
  step?: number
  /** Option labels for an enum field; default `{ label: humanize(v), value: v }` for each value in `rule.enum`. */
  options?: { label: string; value: string }[]
}

export interface EntityDialogLabels {
  createTitle: (name: string) => string
  editTitle: (name: string, itemLabel?: string) => string
  createSubmit: string
  editSubmit: string
  cancel: string
  noneOption: string
  unreachable: string
  pageFailed: string
}
```

#### Props, Emits, Slots & Exposed API

- **Props:**
  - `open?: boolean` (`v-model:open`)
  - `defaultOpen?: boolean` (default `false`)
  - `record?: T | null` (`null` or `undefined` for create mode; a record `T` for edit mode)
  - `schema: EntitySchema` (the generated `schema.<Type>Input`, or a hand-written schema)
  - `create?: (body: TInput) => Promise<T>`
  - `update?: (id: any, body: Partial<TInput>) => Promise<T>`
  - `idKey?: string` (property name of the record's ID for `update`, default `'id'`)
  - `labelKey?: string` (property name of the record used in the edit title `"Edit <label>"`, default `'name'`, falling back to `'title'` if present and non-empty, else `name`)
  - `name?: string` (singular resource name, e.g. `'product'`; default `'item'`)
  - `title?: string` (explicit dialog title override)
  - `description?: string` (optional dialog description)
  - `defaults?: Partial<TInput> | (() => Partial<TInput>)` (initial field values in create mode)
  - `fields?: EntityFieldConfig[]` (when provided, orders and configures the auto-rendered fields; any schema field not listed is still included after unless `fields` is authoritative — call: when `fields` is given, render the fields listed in `fields` in that order, merging each with `schema[f.name]`; when `fields` is omitted, render every key of `schema` in object key order)
  - `labels?: Partial<EntityDialogLabels>`
- **Emits:**
  - `'update:open': [open: boolean]`
  - `saved: [record: T | null]` (`record` returned by `create` or `update`; not emitted when an edit closes with zero changes)
  - `error: [error: unknown]`
- **Slots:**
  - `default?: (props: { state: TInput; record: T | null; schema: EntitySchema }) => unknown` — replaces the auto-rendered field stack inside the `<Form>` (the `Alert` and the Cancel/Submit footer buttons remain rendered by `EntityDialog` around the slot, so a custom slot never has to re-write the `Alert` or footer buttons).
  - `[field: `${string}-field`]: ((props: { state: TInput; record: T | null; rule: EntityFieldRule; field: EntityFieldConfig }) => unknown) | undefined` — replaces a single field's control inside its `<FormField>` when using auto-rendered fields.
- **Behavior:**
  1. **State initialization on open / record change:**
     - Whenever the dialog opens (`open` becomes `true`) or `props.record` changes while open:
     - Build the fresh state object from `schema` keys (plus any keys in `defaults` or `fields`):
       - In **edit mode** (`props.record != null`): for each key `k`, copy `props.record[k]` (converting `undefined` on a `nullable` field to `null`).
       - In **create mode** (`props.record == null`): start from `typeof props.defaults === 'function' ? props.defaults() : props.defaults`, and for any key `k` in `schema` not in `defaults`:
         - if `rule.nullable` → `null`
         - else if `rule.kind === 'number'` → `0`
         - else if `rule.kind === 'boolean'` → `false`
         - else if `rule.kind === 'list'` → `[]`
         - else if `rule.kind === 'record'` or `'object'` → `{}`
         - else if `rule.enum?.length && rule.required` → `rule.enum[0]!`
         - else → `''`
     - Assign into `draft` (`reactive`), clear `problem.value = ''`, and increment `formKey.value++` (or call `form.value?.clear()`) so no errors from an earlier open remain.
  2. **Auto-rendered controls (when `$slots.default` is not given):**
     - Measure width via `useWidth(panelOrViewport, { prepaint: false })` (or `useWeft()`).
     - For each field:
       - Wrap in `<FormField :label="fieldLabel" :name="field.name" :hint="field.hint">`.
       - If slot `${field.name}-field` exists, render it.
       - Else if `rule.enum && rule.enum.length > 0`:
         - Build options: use `field.options ?? rule.enum.map(v => ({ label: humanize(v), value: v }))`, prepending `{ label: t.value.noneOption, value: '' }` when `!rule.required && !rule.nullable` and `''` is not already in the options.
         - If `field.control === 'radio' || (field.control !== 'select' && options.length <= 4 && width.value !== 'narrow')`, render `<RadioGroup v-model="(draft as any)[field.name]" :items="options" orientation="horizontal" />`.
         - Else render `<Select v-model="(draft as any)[field.name]" :options="options" :placeholder="field.placeholder" />`.
       - Else if `rule.kind === 'boolean' || field.control === 'checkbox' || field.control === 'switch'`:
         - Render `<Switch v-if="field.control === 'switch'" v-model="(draft as any)[field.name]" />` or `<Checkbox v-else v-model="(draft as any)[field.name]" />`.
       - Else if `rule.kind === 'number' || field.control === 'number'`:
         - Render `<InputNumber v-model="(draft as any)[field.name]" :min="rule.min" :max="rule.max" :step="field.step" :placeholder="field.placeholder" />`.
       - Else if `field.control === 'textarea'`:
         - Render `<Textarea v-model="(draft as any)[field.name]" :placeholder="field.placeholder" />`.
       - Else:
         - Render `<Input v-model="(draft as any)[field.name]" :type="rule.email ? 'email' : rule.url ? 'url' : 'text'" :placeholder="field.placeholder" />`.
  3. **Diffing and saving on `@submit="save"`:**
     - In **edit mode** (`props.record != null`):
       - Compute `changed = changes(values, props.record, props.schema)`:
         - For each key `k` of ` props.schema` (or `values` / `props.record`):
           - Let `was = props.record[k] ?? (props.schema[k]?.nullable ? null : undefined)`.
           - Let `now = k in values ? values[k] : undefined`.
           - If `k in values` and `!sameValue(now, was)`, set `changed[k] = now`.
       - If `Object.keys(changed).length === 0`, set `open.value = false` and return without calling `props.update`.
       - Otherwise `const saved = await props.update!(props.record[props.idKey ?? 'id'], changed as Partial<TInput>)`, set `open.value = false`, and `emit('saved', saved)`.
     - In **create mode** (`props.record == null`):
       - `const saved = await props.create!(values)`, set `open.value = false`, and `emit('saved', saved)`.
  4. **Error handling (`entityProblem` in `entity.ts`):**
     - Structural duck-typing for `ApiError` (checks `e instanceof Error && typeof (e as any).status === 'number' && typeof (e as any).code === 'string' && typeof (e as any).fields === 'object' && (e as any).fields !== null`, so it works with any app's generated `ApiError` class):
       - If not an `ApiError`-shaped object: `console.error(e)` and set `problem.value = t.value.pageFailed`, `emit('error', e)`.
       - If `e.code === 'network'`: set `problem.value = t.value.unreachable`, `emit('error', e)`.
       - Otherwise split `e.fields` into `knownFields` (keys that exist in `props.schema` or in the rendered `fields`) and `extraMessages` (values of `e.fields` whose key is not a rendered field in the form):
         - Call `form.value?.setErrors(knownFields)`.
         - If `extraMessages.length > 0`, set `problem.value = extraMessages.join(' ')`.
         - Else if `Object.keys(knownFields).length === 0`, set `problem.value = e.message`.

### 3. `DataTable` (`packages/ui/src/data/DataTable.vue`)

`DataTable` is a Vapor component `<script setup vapor lang="ts" generic="T extends Record<string, any> = Record<string, any>, TInput extends Record<string, any> = Record<string, any>">`.

#### Types (`packages/ui/src/data/entity.ts`)

```ts
import type { TableColumn, TableFetch, TableLabels } from './table.ts'

/** The shape `weft gen` writes on `api.<module>` for a `data.Resource`. */
export interface DataResource<T, TInput = Partial<T>> {
  list: TableFetch<T>
  create?: (body: TInput) => Promise<T>
  update?: (id: any, body: Partial<TInput>) => Promise<T>
  remove?: (id: any) => Promise<void>
}

/** One declarative filter control in DataTable's toolbar. */
export interface DataTableFilter {
  /** The filter key sent as `filter[key]=value`. */
  key: string
  /** The FormField label above the control; default humanized from `key`. */
  label?: string
  /** The choices, as `RadioGroup` and `Select` take them (the library's word for a list of choices is `items`); a string is its own label and value. When the first choice is not `''`, an `{ label: allLabel || t.anyFilter, value: '' }` choice is prepended automatically unless `allLabel: false`. */
  items: (string | { label: string; value: string })[]
  /** Label for the auto-prepended `''` choice; default `labels.anyFilter` (`'Any'`), or `false` to add none. */
  allLabel?: string | false
  /** Control style: default `'radio'` when `<= 4` total items (and not narrow), else `'select'`. */
  control?: 'radio' | 'select'
}

export interface DataTableLabels extends TableLabels, EntityDialogLabels {
  search: string
  searchPlaceholder: string
  anyFilter: string
  booleanYes: string
  booleanNo: string
  newAction: (name: string) => string
  actionsColumn: string
  editAction: string
  deleteAction: string
  deleteTitle: (itemLabel: string) => string
  deleteDescription: string
  deleteConfirm: string
}
```

#### Props, Emits, Slots & Exposed API

- **Props:**
  - `columns: TableColumn<T>[]` (if `update` or `remove` is provided and `columns` has no column with `key: 'actions'`, `DataTable` appends `{ key: 'actions', label: t.actionsColumn, align: 'end' }` automatically; if `columns` already includes `key: 'actions'`, it uses that column's position and label)
  - `resource?: DataResource<T, TInput>`
  - `fetch?: TableFetch<T>` (overrides `resource.list`)
  - `create?: (body: TInput) => Promise<T>` (overrides `resource.create`)
  - `update?: (id: any, body: Partial<TInput>) => Promise<T>` (overrides `resource.update`)
  - `remove?: (id: any) => Promise<void>` (overrides `resource.remove`)
  - `schema?: EntitySchema` (passed to the built-in `EntityDialog`)
  - `fields?: EntityFieldConfig[]` (passed to the built-in `EntityDialog`)
  - `defaults?: Partial<TInput> | (() => Partial<TInput>)` (passed to the built-in `EntityDialog`)
  - `name?: string` (singular resource name, e.g. `'product'`; default `'item'`)
  - `idKey?: string` (default `'id'`)
  - `labelKey?: string` (default `'name'`, used for `"Delete <label>?"` and `"Edit <label>"`)
  - `searchable?: boolean` (default `true`; shows the Search `Input` in the toolbar)
  - `search?: string` (`v-model:search`)
  - `defaultSearch?: string` (default `''`)
  - `searchPlaceholder?: string`
  - `searchDebounce?: number` (default `250`, passed to `Table`)
  - `filterDefs?: DataTableFilter[]` (declarative filter controls in the toolbar)
  - `filters?: Record<string, string>` (`v-model:filters`)
  - `defaultFilters?: Record<string, string>`
  - `perPage?: number` (default `20`)
  - `page?: number` (`v-model:page`)
  - `defaultPage?: number` (default `1`)
  - `sort?: string | null` (`v-model:sort`)
  - `defaultSort?: string | null`
  - `selectable?: boolean`
  - `selected?: RowKey[]` (`v-model:selected`)
  - `defaultSelected?: RowKey[]`
  - `caption?: string`
  - `hideCaption?: boolean` (default `true` when `caption` is given)
  - `emptyTitle?: string` (when no `#empty` slot is given, `DataTable` renders an `<EmptyState :title="emptyTitle" :description="emptyDescription" :icon="emptyIcon" variant="ghost" />`)

### 5. `weft scaffold` (`cmd/weft/scaffold.go`, `cmd/weft/scaffold_test.go`)

```text
weft scaffold <name> <field[:type[:modifier...]]> ... [--plural <word>] [--api]
```

#### Command-line rules

1. **Resource name (`<name>`) and `--plural <word>`:**
   - Must be a lowercase identifier (`^[a-z][a-z0-9_]*$`, e.g. `product`, `line_item`).
   - Unless `--plural <word>` is given (which must also match `^[a-z][a-z0-9_]*$`), `<name>` is pluralized by a deterministic English pluralizer (`pluralOf(singular)`):
     - common irregulars/uncountables (`person` → `people`, `child` → `children`, `category` → `categories`, `status` → `statuses`, `address` → `addresses`, `box` → `boxes`, `bus` → `buses`, `quiz` → `quizzes`, `leaf` → `leaves`, `knife` → `knives`, `life` → `lives`, `series` → `series`, `news` → `news`, `equipment` → `equipment`);
     - consonant + `y` → `ies`;
     - `s`, `x`, `z`, `ch`, `sh` → `es`;
     - default → `s`.
   - No plural detection is attempted on `<name>`. Refused with one sentence: reserved package/folder names (`data`, `auth`, `warp`, `app`, `web`, `test`, `main`), Go's keywords and predeclared names, standard library packages the generated files may import, names the story test uses, `user`/`users` (auth's), and names whose Go type would collide with Weft's, the client's or the package's own (`Module`, `Record`, `List`, `Query`, `Login`, `Setup`, `Message`). The chosen plural is shown in the output of what was written so the author sees it immediately.
   - Package and folder name: `app/<plural>`, route path `/<plural>`, table name `<plural>`, Go struct name `PascalCase(singular)`, permission prefix `<plural>`.

2. **Field syntax (`<field[:type[:modifier...]]>`):**
   - At least one field is required; otherwise exit 2 with usage.
   - If any argument contains `|` or `(`, refuse with one sentence showing the shell-safe comma form: `weft scaffold: write enum choices separated by commas after enum=, as in status:enum=draft,live.`
   - If any field argument contains `?` (which zsh reads as a pattern, so it can only arrive quoted), refuse with one sentence showing the modifier: `weft scaffold: write a field that may be null with the modifier nullable, as in sale:float:nullable.`
   - Field name: snake_case (`^[a-z][a-z0-9_]*$`). `id`, `created_at` and `updated_at` are refused with one sentence saying they come from `data.Record`. Duplicate field names are refused.
   - Type (default `string` when omitted; no name-based inference, and no hidden `max=120` on `string`):
     - Supported types:
       | Type | Go type (non-null / `:nullable`) | `warp` rules from type | `data` tag | UI table / dialog |
       | --- | --- | --- | --- | --- |
       | `string` (default) | `string` / `*string` | none | `sort,search` | text cell; first string field is `rowHeader: true` with link to `/<plural>/${row.id}` |
       | `text` | `string` / `*string` | none | `search` | `control: 'textarea'` in `EntityDialog` |
       | `email` | `string` / `*string` | `email` | `sort,search` | `type="email"` |
       | `url` | `string` / `*string` | `url` | `sort,search` | `type="url"` |
       | `int` | `int64` / `*int64` | none | `sort` | `align: 'end'`, formatted with `toLocaleString()`, `step: 1` |
       | `float` | `float64` / `*float64` | none | `sort` | `align: 'end'`, formatted with `toLocaleString()` (`step` unset unless given in `fields`) |
       | `bool` | `bool` / `*bool` | none | `sort,filter` | `Badge` (`labels.booleanYes` / `labels.booleanNo`) in table, `Checkbox` in dialog, filter in toolbar |
       | `date`, `datetime` | `time.Time` / `*time.Time` | none | `sort` | with `--api` only: without it refused, exit 1, `weft scaffold: field "<name>" is a <type>, and date and time fields in the pages weft scaffold writes land in Weft 0.2.0; give --api to write only the Go for now.` (Amended 2026-11-27: the dialog has no date control and the schema does not say a field is a time; both are 0.2.0.) |
       | `enum=a,b` | `string` / `*string` | `enum=a\|b` | `sort,filter` | `Badge` in table, filter in toolbar |
     - Unsupported / future types:
       - `belongs_to`, `has_many`, `many_to_many`: refused with exit 1, `weft scaffold: field "<name>" has type "<type>", and relations land in Weft 0.3.0 (W3); use a scalar type for now.`
       - `image`, `file`: refused with exit 1, `weft scaffold: field "<name>" has type "<type>", and file attachments land in Weft 0.4.0 (W6); use a scalar type for now.`
       - `json`, `translated`: refused with exit 1, `weft scaffold: field "<name>" has type "<type>", which lands in Weft 0.6.0 (W7); use a scalar type for now.`
       - Any other unknown type: refused with exit 2 naming the allowed types.
   - Modifiers (after `:type`, separated by `:`, in any order, each once):
     - `nullable`: the field is a pointer in Go (`*float64`, `*string`, `*time.Time`) and `| null` in TypeScript, e.g. `sale:float:nullable`, `body:text:nullable:max=5000`, `kind:enum=a,b:nullable`.
     - `required`: adds `required` to the `warp` tag. Refused on `bool` or with `nullable`, in either order, with one sentence.
     - `unique`: adds `unique` to the `warp` tag. Refused on `bool`, `text`, `date`, `datetime` with one sentence (since `warp` only allows `unique` on text and numbers), and on an `enum` with one choice, which could hold one record.
     - `min=N`, `max=N`: adds `min=N` or `max=N` to the `warp` tag on `string`, `text`, `email`, `url`, `int` or `float` ( validating that `N` is a non-negative integer for text types, a whole number for `int`, and a decimal number for `float`); refused on `bool`, `date`, `datetime` or `enum` with one sentence.

3. **Pre-flight checks (nothing written if any check fails):**
   - Must be inside a Weft app (`findApp(".")`, passing `ensure`).
   - Refuse if `app/<plural>` already exists (`weft scaffold: app/<plural> already exists; remove it by hand or choose another resource name.`).
   - Unless `--api` is passed, refuse if `web/pages/<plural>`, `web/pages/<plural>.vue` (both would make `/<plural>`), `web/components/<Plural>Table.vue` or `web/components/<Singular>View.vue` already exists.
