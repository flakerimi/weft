# Warp Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small shop app in the repository, driven by the suite, in which one resource goes end to end: stored in SQLite, behind a login, its TypeScript types generated from Go, a table with an edit dialog, and a page per record.

**Architecture:** The core (`warp/`) gains what every later layer needs: named routes, typed dependencies between modules, a body field and a `readonly` rule, updates of only what was sent, cross-site protection, and a description of itself. On it sit `warp/data` (a store on `database/sql`), `warp/auth` (a signed-cookie login) and `warp/warptest`. `weft gen` turns the app's description into a typed TypeScript client. The page build and `warp.Serve` learn pages whose paths are known only at run time. `examples/shop` uses all of it as a developer would.

**Tech Stack:** Go 1.26 standard library only in `warp/` (`database/sql`, `net/http.CrossOriginProtection`, `crypto/pbkdf2`, `crypto/hmac`); the pure-Go SQLite driver `modernc.org/sqlite` only in the nested modules `dbtest/` and `examples/shop/` (run `go list -m -versions modernc.org/sqlite` and take the latest); Vue `3.6.0-rc.16`, TypeScript, Vite as the repository pins them.

**Spec:** `docs/superpowers/specs/2026-11-25-warp-slice-design.md`. It extends `docs/superpowers/specs/2026-11-23-warp-design.md`. Executors read the slice design in full; where this plan and the design differ, the design decides what is built and the plan decides names.

## Global Constraints

- **Inherited:** every rule in `AGENTS.md`, and the Global Constraints of `docs/superpowers/plans/2026-11-25-warp-core.md`.
- **`warp/` imports only the standard library.** A driver appears only in `dbtest/go.mod` and `examples/shop/go.mod`.
- **Nothing registers itself from `init`.** A module's `Register` does no file, network or database work; the database opens in `Migrate`.
- **Every error is one sentence** that names the thing and says what to do. A registration mistake starts `warp: ` and is reported through `app.Err()`; none panics. An API answer never carries a Go error's text unless the handler returned a `*warp.Error`.
- **One error shape**, and W1's limits stand: a 1 MiB body, 64 levels, at most 100 listed fields and 16 KiB of keys.
- **Nothing from a request is unbounded.** Any new thing read from a request has a stated limit and a test at the limit.
- **JSON names are snake_case.** Generated TypeScript keeps the JSON names as they are.
- **Vapor only** for any `.vue` file; styles use `--weft-*` tokens with fallbacks; after changing a component's props, docs or examples run `pnpm catalog`.
- **Generated files are never committed or edited:** `web/.weft-types/`, `.weft/`, any `dist/`, `catalog/components.json` (regenerated by its script only).
- **Never delete.** Files move with `git mv`. Never run `scripts/publish-site.sh`, `scripts/rollback-site.sh` or `lisa`. Never push.
- **Test first**, see it fail for the expected reason, then pass; check the key test catches a deliberate mistake. Before each commit run the suite in `AGENTS.md` plus, once they exist, `(cd dbtest && go test ./...)`.
- **Commits:** `Area: what changed` and a short list; no `Co-Authored-By`; `git add` by name.
- **Work in** `.worktrees/warp-slice`, branch `warp-slice`.

## Review Focus

1. **A request without a session, or from another site.** Every route of the shop's resource, and `logout`, answers 401 without a session and 403 for a cross-site `POST`, `PATCH` or `DELETE`, including routes that take no body. (Tasks 3, 8, 12.)
2. **An update that sends one field.** `PATCH {"price": 5}` changes the price and nothing else; `{"name": ""}` is a 422; `{"id": 9}` and `{"created_at": …}` are 400; a name another record has is a 422 on `name`. (Tasks 2, 7.)
3. **A database that does not match the code.** A new field adds a column; a field whose type changed stops the app with one sentence and changes nothing; a failed transaction leaves no half-written record. (Task 6.)
4. **Generating types must not run the app.** `weft gen` with a wrong `.env`, no database file and no `AUTH_SECRET` still writes `api.ts`, or fails with the registration mistake's sentence, and never creates a database. (Tasks 4, 6, 9.)
5. **A page for a record that does not exist, and a path that merely looks like one.** `/products/999` serves the shell and the page says not found; `/products/1/extra` and `/products/` are 404; an exact page always wins over a pattern. (Task 10.)

### Task 1: Names, dependencies and starting without listening

**Files:** Modify `warp/app.go`, `warp/run.go`, `warp/env.go`; Create `warp/proxy.go`; tests beside each.

**Interfaces — Produces:**
```go
type Route struct { Module, Name, Method, Path string; In, Out reflect.Type; Status int; Permission string }
func Name(name string) RouteOption
func Permission(permission string) RouteOption          // records only
func Options(opts ...RouteOption) RouteOption            // several as one, applied in order
func Provide[T any](app *App, value T)
func Need[T any](app *App, module string) T               // the zero T and a mistake when nothing was provided
func (a *App) Start(ctx context.Context) error            // every Migrate, then every Start; stops what started if one fails
func (a *App) Stop(ctx context.Context) error             // every Stop, in reverse
func (a *App) ClientIP(r *http.Request) string            // without the port
func (a *App) IsHTTPS(r *http.Request) bool
// Config gains: TrustProxy bool (TRUST_PROXY on), URL string (APP_URL; default "http://localhost:" + Port)
```

- `Module` is the name of the module whose `Register` is running; empty outside one.

- `Run` is rebuilt on `Start` and `Stop`; its behaviour and tests do not change.
- With `TrustProxy`, `IsHTTPS` is true for `X-Forwarded-Proto: https` and `ClientIP` is the last address in `X-Forwarded-For`; without it both read the connection.
- Sentences: `warp: module "products" needs the "data" module; list data.Module() before it in app/modules.go.` (outside a module, `warp: the app needs the "data" module; list data.Module() in app/modules.go.`); `warp: two modules provide a *data.DB; list only one of them.`; `warp: module "products" has two routes named "list" (GET /products and GET /products/all); give one a warp.Name.`; `warp: Name("") is empty; give the route a name.`; `APP_URL is "x"; set it to an address like https://shop.example.com.`

### Task 2: The body field, `readonly`, and updates of what was sent

**Files:** Modify `warp/bind.go`, `warp/validate.go`, `warp/route.go`; tests beside each.

**Interfaces — Consumes:** Task 1's `Route`. **Produces:**
```go
// tags: `body:"json"` on one struct field of an input; the rule `readonly` in a warp tag;
//       `query:"filter"` on a map[string]string field
func Sent(ctx context.Context, key string) bool   // did the JSON body have this top-level key
func SentKeys(ctx context.Context) []string       // in the body's order
// an input type, or the type of its body field, may have: Validate(ctx context.Context) error
```
- **Body field:** its type is a struct; its fields are the input's JSON fields, flattened exactly as an embedded struct's are (the same index paths), so errors and `Sent` use `name`, never `body.name`. An input with a body field has no `json` fields of its own, has one body field, and is on a method that reads a body.
- **`readonly`:** the field is left out of what the body may send (sending it is the existing 400, `The body has the field "id", which this route does not take.`) and is never validated. It carries no other rule and only goes on a `json` field.
- **`Patch` routes:** tag rules run only on fields the body sent. Every other route, and `Validate(v)` called directly, checks every field as today.
- **The input's `Validate`:** called after the tag rules pass, on the input and on its body field if either has the method (value or pointer receiver). A returned `*warp.Error` is answered as it is; another error as a handler's error.
- **`filter`:** `filter[status]=live` fills `map["status"] = "live"`; a key given twice keeps the first; more than 32 keys, or a key longer than 64 bytes, is 400 `bad_request` with `The query has more filter[...] keys than a route takes (32).` or `A filter[...] key is longer than 64 bytes.`
- Registration sentences (route prefix as elsewhere): `…: UpdateIn.Body is tagged body:"json" and is a string; make it a struct.`; `…: UpdateIn has a body field and the json field Name; move Name into the body's type.`; `…: UpdateIn has two body fields, Body and Other; keep one.`; `…: ShowIn.Body is tagged body, and GET reads no body; remove it.`; `…: UpdateIn.Body is tagged body:"xml"; the only body kind is json.`; `Product.ID has the rule "readonly" beside other rules; a readonly field is never read, so remove them.`; `…: ShowIn.Page is tagged query and readonly; readonly is for json fields.`; `…: ListIn.Filter is a map[string]int; a filter map is a map[string]string.`

### Task 4: The app describes itself

**Files:** Create `warp/describe.go`, `warp/describe_test.go`; Modify `warp/run.go`.

**Interfaces — Consumes:** Tasks 1 and 2. **Produces:**
```go
func (a *App) Describe() (Description, error)
type Description struct { Routes []RouteInfo `json:"routes"`; Types []TypeInfo `json:"types"` }
```
- `RouteInfo`: module, name, method, path (with `/api`), status, permission, the path parameters and query fields (name, TypeScript type, optional), the body's type name and whether it is partial (a `Patch`), and the output's type (name, or `null` for `None`, and whether it is a list).

A generic type's name is its base name with its arguments' names appended (`List[Product]` is `ListProduct`).

- Routes added with `Handle` are listed with no input and no output. Order: as registered; types in order of first use.
- `(*App).Serve`, when `WARP_DESCRIBE=1`: after its `Err()` check, writes the description as indented JSON to standard output and returns nil (or returns `Describe`'s error) without calling `Start` or listening.

### Task 6: A store on a database

**Files:** Create `warp/data/module.go`, `dialect.go`, `table.go`, `store.go` and unit tests that need no database (`table_test.go`: the columns and SQL text for a struct); Create the module `dbtest/` (`go.mod`, `store_test.go`, `migrate_test.go`, `tx_test.go`); Modify `AGENTS.md` (the two nested modules, their one allowed dependency, `(cd dbtest && go test ./...)` in the test list).

**Interfaces — Consumes:** Tasks 1, 2, 5. **Produces:**
```go
func Module() warp.Module                    // name "data"; reads DB_DRIVER and DB_URL; provides *DB; opens and migrates in Migrate; closes in Stop
func For(app *warp.App) *DB                  // warp.Need[*DB](app, "data")
type DB struct{ /* … */ }
func (db *DB) SQL() *sql.DB                  // nil until the app has started
func (db *DB) Tx(ctx context.Context, fn func(ctx context.Context) error) error
type Record struct {
    ID        int64     `json:"id" warp:"readonly"`
    CreatedAt time.Time `json:"created_at" warp:"readonly"`
    UpdatedAt time.Time `json:"updated_at" warp:"readonly"`
}
type ID struct { ID int64 `path:"id"` }
func NewStore[T any](db *DB, table string) *Store[T]   // T embeds Record by value; records the table on db
func (s *Store[T]) Get(ctx context.Context, id int64) (T, error)            // warp.NotFound(`No <singular> has id 7.`) when missing
func (s *Store[T]) Create(ctx context.Context, v *T) error                  // sets ID and both times on v
func (s *Store[T]) Update(ctx context.Context, id int64, v *T, fields []string) (T, error) // writes the named json fields and updated_at; returns the record
func (s *Store[T]) Delete(ctx context.Context, id int64) error
```
- Columns are the `json` names of `T`'s fields (embedded structs flattened); `json:"-"` is not stored. SQLite types: string `TEXT`, ints and bool `INTEGER`, floats `REAL`, `time.Time` `TEXT` (RFC 3339 with nanoseconds, UTC), `[]byte` `BLOB`; a pointer is the same and nullable; everything else is `NOT NULL` with the zero value as default, so adding a column to a table with rows works. Another field type is a mistake: `warp: products: Product.Tags is a []string, which a store cannot keep; use text, a number, a bool, a time or bytes, or tag it json:"-".`
- `id` is `INTEGER PRIMARY KEY AUTOINCREMENT`. A field with the rule `unique` gets a unique index named `<table>_<column>_unique`.
- **Migrate:** a missing table is created; a missing column is added; a column of another type stops the start: `warp: table products has column price as TEXT, and Product.Price needs REAL; change the field back, or alter the column yourself, since Warp never changes or drops a column.` Extra columns in the table are left alone. All of it in one transaction.
- **Tx:** `fn`'s context carries the transaction; store calls with it use it; a nested `Tx` joins the outer one; a panic rolls back and is re-panicked.
- A unique violation from `Create` or `Update` is returned as `warp.Invalid(map[string]string{"<field>": "This is already taken."})`. The dialect recognises its driver's error by its text, with a test that fails if the driver rewords it.
- Sentences at start: `warp: DB_DRIVER is not set; add DB_DRIVER=sqlite and DB_URL=file:data/app.db to .env.`; `warp: no database driver is named "sqlite"; import one in main.go, such as _ "modernc.org/sqlite".`; `warp: DB_DRIVER is "oracle"; this version of Warp speaks sqlite.`; `warp: the database at file:data/app.db cannot be opened (<err>); check DB_URL in .env.` A `file:` path's folder is made if it is missing. A store used before the app started: `warp: the products store was used before the app started; use it from a handler, or after Start.`
- The dialect is one small type (placeholder, quoting, column type per Go kind, reading a table's columns, recognising a unique violation); the store never writes SQLite-specific text itself.

### Task 7: Lists and the five routes

**Files:** Create `warp/data/query.go`, `warp/data/resource.go`, `warp/data/query_test.go`; `dbtest/list_test.go`, `dbtest/resource_test.go`.

**Interfaces — Consumes:** Tasks 2, 6. **Produces:**
```go
type Query struct {
    Page    int               `query:"page" warp:"min=1"`
    PerPage int               `query:"per_page" warp:"min=1,max=100"`
    Sort    string            `query:"sort"`
    Q       string            `query:"q" warp:"max=200"`
    Filter  map[string]string `query:"filter"`
}
type List[T any] struct { Items []T `json:"items"`; Total int `json:"total"`; Page int `json:"page"`; PerPage int `json:"per_page"` }
func (s *Store[T]) List(ctx context.Context, q Query) (List[T], error)
type ResourceOption func(*resourceConfig)
func Each(opts ...warp.RouteOption) ResourceOption                               // on all five
func PerAction(fn func(action string) []warp.RouteOption) ResourceOption          // action is list, show, create, update or remove
func Resource[T any](app *warp.App, path string, store *Store[T], opts ...ResourceOption)
```
- A field takes part in lists by its `data` tag: `data:"sort"`, `"filter"`, `"search"`, any of them comma-separated. `id`, `created_at` and `updated_at` can always be sorted on. `Sort` is a field's JSON name, `-` in front for descending; default `-id`. `Q` matches any `search` field containing the text, case-insensitively, with `%` and `_` in it taken literally. `Filter` is equality on a `filter` field, the value converted to the field's kind.
- Page 0 means 1; per page 0 means 20. `Items` is never null.
- 400s, `bad_request`, with `fields`: `sort: products cannot be sorted by "cost"; use one of: created_at, id, name, price, updated_at.`; `filter[size]: products cannot be filtered by "size"; use one of: status.`; `filter[price]: Send a number.`
- A `data` tag naming something else, or `search` on a field that is not text: `warp: products: Product.Price is tagged data:"search", and search is for text; use sort or filter.`
- `Resource` registers, under `path`, with the names `list`, `show`, `create`, `update`, `remove`: `GET path` (`Query` → `List[T]`), `GET path/{id}` (`ID` → `T`), `POST path` (a body of `T` → `T`, 201), `PATCH path/{id}` (the id and a body of `T`; writes `warp.SentKeys`; with no sent key it answers the record unchanged), `DELETE path/{id}` (`ID` → `None`).
