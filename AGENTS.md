# AGENTS.md

This file is for agents working on Weft itself. To build with Weft, read the skills in `skills/` instead, or https://weft.base.al/llms.txt.

Weft is one UI system for Go and Vue apps. It has Vapor components, a page build, and a Go package that serves the build from one binary. It is pre-alpha, and nothing is published to npm.

## Layout

| Path | What it is |
| --- | --- |
| `serve.go`, `files.go`, `manifest.go`, `version.go` | The `weft` Go package (`github.com/flakerimi/weft`): `Serve`, `WithFiles`, `Version`. Standard library only. |
| `cmd/weft/` | The `weft` command: `create`, `dev`, `build`, `upgrade`, `version`, `update`. A release stages the bundle (the packages, the Go package, the catalogue and the template) into `cmd/weft/bundle/` for `go:embed`; in git that folder holds only `README.md`, and a development build reads a bundle from the folder `$WEFT_BUNDLE` names. |
| `packages/themes/` | Tokens and the `neutral`, `lisa` and `weft` themes. `dist/` is generated. |
| `packages/ui/` | `@weft/ui`. Components are in `src/<group>/<Name>.vue` with `<Name>.docs.md`, the accessibility composables in `src/headless/`, examples in `examples/<Name>/`, tests in `test/`. |
| `packages/vite/` | `@weft/vite`: the page build (`bin/weft-build-pages.mjs`, `src/build.ts`), the page dev server (`bin/weft-dev.mjs`, `src/dev.ts`), auto-imported components (`src/auto-import.ts`), server rendering, Markdown content, islands. |
| `templates/app/` | The app `weft create` writes. A file ending `.tmpl` is rendered with the delimiters `[[` and `]]` and loses the suffix. |
| `catalog/components.json` | The component catalogue, generated by `scripts/catalog.ts` (`pnpm catalog`). Never edit it by hand. |
| `site-src/` | weft.base.al. It has its pages, the docs in `content/docs/`, the gallery in `gallery/`, the files for agents in `agents/`, the server in `main.go`, and Go tests over the build. |
| `skills/` | Claude Code skills for people building with Weft, served at `/skills/<name>`. |
| `playground/` | A Go binary embedding a Vite app that uses the components. |
| `bench/` | The benchmark against Astro. |
| `scripts/` | Builds and releases: `site.sh`, `playground.sh`, `bundle.sh` (stages the bundle `weft` carries), `release.sh` (stages it into `cmd/weft/bundle/` and builds the binaries), `publish-site.sh`, `rollback-site.sh`, `catalog.ts`, `sizes.ts`. |
| `docs/superpowers/specs/` | The design, `2026-11-20-weft-design.md`, with its phases. |
| `docs/superpowers/plans/` | The plans, one per stage, each with Global Constraints and a Review Focus. |
| `docs/parity.md`, `docs/sizes.md`, `docs/design/` | The comparison with Nuxt UI, each component's size, and the approved designs. |

## Build and test

You need Go 1.26, Node 22.18 or later and pnpm 10. Run everything from the repository root.

```sh
pnpm install
pnpm --filter @weft/ui test           # while working on components
pnpm test                             # every package; builds @weft/themes and @weft/ui first
pnpm typecheck
scripts/playground.sh build           # go test needs all three builds
scripts/site.sh build
pnpm --filter weft-bench build
go vet ./...
go test ./...
```

- `scripts/site.sh` and `scripts/playground.sh` without `build` also run the server, on `:8080`.
- After you change a component's props, its `.docs.md` or an example, run `pnpm catalog`. A stale catalogue fails `pnpm test` (`packages/ui/test/catalog.test.ts` rebuilds it and compares). The site build checks only the examples: it fails when an example file is unlisted, changed or gone, not when props or docs changed.
- `node scripts/sizes.ts` rewrites `docs/sizes.md`.
- `go test ./cmd/weft` stages a bundle, makes apps and installs them from the npm registry, runs `weft dev`, and builds a release with `scripts/release.sh`, which takes minutes. `go test -short ./cmd/weft` skips all of that; `scripts/release.sh` runs the `-short` tests, since the full ones run it.

## How work is done

1. **Plan.** Work follows a plan in `docs/superpowers/plans/`, and the plan follows the spec. Its Global Constraints bind every task.
2. **Test first.** Write the failing test, run it, and see it fail for the reason you expect. Then implement, and see it pass. Check that the key tests catch a deliberate mistake.
3. **Run the full suite** (above) before each commit.
4. **Commit** with a message like `Area: what changed`, then a short list of the changes. Put no `Co-Authored-By` line in it.
5. **Review.** A reviewer who did not write the commit reviews it against the plan's constraints and Review Focus. Findings are fixed in a follow-up, with the tests that cover them run again.

Briefs and reports for a plan's tasks live in `.superpowers/sdd/<plan>/`, which git ignores.

## Rules

- **Vapor only.** Every component is `<script setup vapor lang="ts">`. Never use the Options API, `getCurrentInstance`, `app.config.globalProperties`, `v-memo` or VNode render functions, and never install `vaporInteropPlugin`.
- **Pinned versions.** `vue` is pinned to exactly `3.6.0-rc.16`. Before adding any dependency, run `npm view <pkg> version` and use the latest.
- **Go uses the standard library only.** Nothing is compressed, rendered or hashed per request: it all comes from the build's manifest.
- **Styles use only `--weft-*` tokens**, each with a fallback. New tokens go in `@weft/themes`.
- **Components adapt from inside**, through `useWeft()` and `useWidth()`. Never write a `Mobile*` variant, and never check device names.
- **Error messages** are one sentence that names the file and says what to do.
- **No npm publishing.** Every package is `private`.
- **Never delete with `rm`.** Use `trash`, which can be undone. Never delete the owner's files, and ask before deleting anything. Tests may remove only their own temporary folders.
- **Git.** Never use a bare `git stash`. Commit or push only when asked.
- **Publishing is the owner's step.** Never run `scripts/publish-site.sh`, `scripts/rollback-site.sh` or `lisa` without `--dry-run`. Releases in `site/releases/` are git-ignored; copy them, never move them.
- **Never edit generated files**: `catalog/components.json`, `packages/themes/dist/`, any `dist/`.
- **Docs describe the code as it is.** Something not built yet goes in `site-src/content/docs/coming-next.md`, with its phase.
